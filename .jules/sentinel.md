## 2025-04-06 - Prevent Stack Trace Exposure in API Exceptions
**Vulnerability:** Information Exposure through overly verbose error messages (CWE-209). Unhandled exceptions in the Mistral agent endpoints (`gap-analysis`, `code-review`, `ask`) were being caught and their string representations (`str(e)`) were being returned directly to the client in HTTP 500 responses.
**Learning:** Returning raw exception details in API responses can leak sensitive internal information, such as stack traces, internal API error messages, or backend configuration paths, aiding an attacker in further reconnaissance or exploitation.
**Prevention:** Always catch generic exceptions securely by returning a generic, safe error message (e.g., "An internal server error occurred.") to the client. Simultaneously, ensure the actual exception details are logged server-side (`logging.error`) for debugging purposes, ensuring both security and maintainability.
